# Check-authored desktop board master01

After washer v1 dual-PASS. Check requires a separate portrait workstation companion after desktop board approval, preserving shared face/frame materials with layout-specific supports. References: desktopv2, portraitv7, washerv1, raccoonv1.

PHASE 3 — CLEAN PROJECT BOARD MASTER 01
DESKTOP STRUCTURAL VARIANT

PROJECT
The Block Laundromat — Illustrated Interactive Homepage.

TASK
Create ONE standalone wooden project-board master
for the approved desktop Light-theme composition.

This is a production-oriented structural asset.
It is not a room illustration or UI mockup.

REFERENCES

1. desktop-concept-v2.png
   PRIMARY GEOMETRY REFERENCE.
   Match the desktop board's identity, approximate
   proportions, perspective, structural supports
   and warm illustrated material language.

2. portrait-concept-v7.png
   Reference for shared board-face/frame design language.
   Do not copy its workstation support geometry into
   this desktop variant.

3. washer-master-v1.png
   Approved washing-machine master.
   Match hand-drawn materials, texture, lighting,
   perspective and edge treatment.

4. raccoon-master-v1.png
   Approved mascot master.
   Match illustration language and outline softness.

GOAL

Produce a complete, physically believable wooden
project board that can later contain real dynamic
Angular DOM/Figma UI elements.

The board must have:

- one large clean cream-colored interior face,
- warm honey-oak outer frame,
- structural support connected to the frame,
- complete edges,
- believable lower supports or posts,
- a subtle supporting lower ledge.

The result must not resemble a floating poster,
generic app card or dashboard component.

CAMERA

Near-frontal 2.5D.

- Upright verticals.
- Slightly visible frame thickness.
- Very mild top/side visibility.
- Minimal perspective distortion.
- Nearly rectangular front surface.
- No exaggerated isometric angle.
- No wide-angle geometry.

The clean board face must remain suitable for
independently positioned DOM UI.

DESKTOP PROPORTIONS

Use desktop-concept-v2.png as the scale reference.

Conceptual desktop board structural area:
approximately 640 CSS pixels wide,
with an upper board region about 500 CSS pixels tall.

The structure must include enough lower support
to establish believable physical grounding
around the original scene's y840 level.

These are scene-placement targets, not canvas
dimensions or rigid generation coordinates.

CLEAN UI FACE

Reserve a large uninterrupted inner cream surface.

Target usable scene area:
approximately 560 × 355 CSS pixels.

Keep this face:

- near-frontal,
- rectangular,
- flat,
- softly textured,
- low contrast,
- fully unobstructed.

No decorations or hardware may cross this area.

The surface must support future:

- project header,
- search,
- sort,
- create/import actions,
- grid or list of projects,
- selection states,
- empty/loading/error states.

These are future interface requirements.

DO NOT DRAW ANY OF THESE UI ELEMENTS.

No cards, pins, thumbnails, project slots,
buttons or search fields.

MATERIALS

- Honey oak wooden frame.
- Cream painted/plaster-like inner surface.
- Dark warm-brown irregular outlines.
- Subtle warm wood grain.
- Matte finish.
- Restrained paper-like texture.
- Diffuse shading.
- Gentle upper-left daylight.
- Soft shadows generally down-right.

Match the approved Light-theme concept and
production masters.

STRUCTURAL SUPPORT

Provide a complete believable frame and support
construction.

The board must be visibly connected to its
own wooden support geometry.

Include:

- stable side posts or equivalent structural support,
- credible frame joints,
- appropriate lower structural connection,
- small functional ledge if present in desktop v2.

Do not invent an elaborate new furniture system.

Do not create a floating rectangle.

Do not add a separate decorative easel unless the
approved desktop concept genuinely requires it.

Complete the lower edges so later compositing
does not expose missing geometry.

The board must remain visually compatible
with its intended wall/architectural placement.

TRANSPARENCY

Use genuine RGBA transparency.

- Transparent exterior.
- Board interior remains opaque cream.
- All frame/support pieces opaque.
- Clean alpha boundaries.
- No painted background.
- No artificial checkerboard.
- No opaque rectangular canvas.
- No white or dark edge halo.
- No baked floor shadow.
- No ambient room shadow attached.

Preserve the entire structural silhouette.

Do not crop frame corners, posts or ledge.

PRODUCTION SEPARATION

The board owns only its own physical structure.

Do not include:

- room walls,
- floor,
- plants,
- shelves,
- lamps,
- laundry baskets,
- towels,
- raccoon,
- washing machine,
- logo,
- project data.

Those belong to independent scene assets.

Do not bake the board into a full-room background.

OUTPUT

Generate ONE high-resolution transparent PNG.

Recommended canvas:
1600 × 1400 pixels or an equivalent resolution
that comfortably preserves the entire structure.

Keep the board centered with sufficient padding.

Do not add labels or an asset-sheet background.

STRICT EXCLUSIONS

No words or numbers.
No interface controls.
No project cards.
No sample thumbnails.
No logo.
No pins or sticky notes.
No decoration inside the clean face.
No room background.
No floor plane.
No baked cast shadow.
No extra furniture.

ACCEPTANCE CRITERIA

PASS only when:

1. The board visibly matches desktop-concept-v2.

2. Its frame and supports form a physically
   believable structural object.

3. Its cream interior is clean, flat and readable.

4. The interior supports an approximately
   560 × 355 CSS-pixel desktop UI region.

5. Its near-frontal perspective permits later
   independent DOM overlays.

6. Warm oak, cream surface, matte rendering and
   soft outlines match approved production masters.

7. The exterior has genuine transparent alpha.

8. The entire structural silhouette is present.

9. No unrelated room objects or decoration
   are baked into the asset.

10. No UI, cards, text, icons or project imagery
    are generated.

11. The board can later be composed into the
    approved desktop room without becoming
    a floating poster.

Generate exactly ONE desktop board master.

Do not generate the portrait workstation variant
in this job.
