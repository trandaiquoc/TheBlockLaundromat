============================================================

Reconstruct the complete Homepage / Project Screen
as a pixel-faithful, layered, maintainable,
interactive 2D/2.5D illustrated environment.

The four approved images define the intended result.

The goal is NOT to produce a visually similar illustration.

object identities, proportions, drawing style,

3. NON-NEGOTIABLE IMAGE PRODUCTION RULES
============================================================

RULE 1 — EXTRACT FIRST, GENERATE SECOND

For every object:

First try to extract the original artwork directly
from the approved reference image.

Retain:
- Original visible pixels.
- Shape.
- Outline.
- Texture.
- Color.
- Perspective.
- Lighting.
- Proportions.
- Relative placement.

Only generate or repaint the parts that cannot be
recovered from the original source.

Never replace an accurately extractable object
with a newly imagined version.

RULE 2 — LOCALIZED RECONSTRUCTION

When an object is partially hidden behind another:

1. Extract the visible portion.
2. Identify the occluded region.
3. Construct a precise missing-region mask.
4. Reconstruct the missing pixels using the surrounding
   image, object geometry and original illustration.
5. Preserve the source pixels outside the missing region.
6. Blend the reconstructed region with the original.
7. Verify that seams and lighting remain coherent.

Use localized inpainting, cloning, texture
reconstruction or other suitable techniques.

Do not regenerate the entire object when only
a small hidden region is missing.

RULE 3 — NO INDEPENDENT REINTERPRETATION

Do not generate a new washing machine, project board,
raccoon or room simply from a text description.

Such independently generated objects frequently have
incorrect perspective, anatomy, geometry and scale.

The existing concept artwork must remain the source.

RULE 4 — TRANSPARENT ASSET OUTPUT

Every extracted movable object must have a correct
alpha channel.

The transparent regions must not contain:
- Black backgrounds.
- White backgrounds.
- Residual silhouettes.
- Yellow/red extraction halos.
- Jagged segmentation artifacts.
- Unwanted shadows from removed objects.

Retain intentional contact shadows where necessary,
or isolate them into a separate shadow layer.

RULE 5 — COMPLETE OCCLUDED GEOMETRY

A removed object must not leave a visible hole
in the background.

If a washing machine is extracted, reconstruct the
wall and floor behind it.

If the board is extracted, reconstruct the wall
behind it.

If a raccoon is extracted, reconstruct the hidden
floor or nearby objects behind it.

If a foreground basket is extracted, reconstruct
the floor and anything partially occluded.

RULE 6 — NO FAKE DATA IN STATIC ARTWORK

Do not retain baked project cards, sample project
names, sample thumbnails, fake buttons or fake
interactive UI in the final static room artwork.

All project-related dynamic content must come from
real application data.

============================================================

Use the original 1672 x 941 image as the master
coordinate system.

- Canvas Y coordinate.
- Original width and height.
- Alpha bounds.
- Layer order.
- Occlusion relationships.
- Anchor point.
- Reconstruction status.
- Intended animation capability.
- Output filename.

Coordinates must be measured from the actual images.

Do not guess coordinates from visual intuition.

During asset preparation, allow full-canvas transparent
layers for exact compositing and alignment.

For runtime optimization, assets may be tightly cropped
as long as their original canvas offsets and anchors
remain recorded in the manifest.

Do not stretch tightly cropped artwork to fit
arbitrary CSS boxes.

Do not use object-fit: fill to hide geometry mismatches.

Use a uniform 16:9 master scene transformation.

Prioritize accurate desktop composition before
introducing responsive adaptations.

This is a responsibility-based example.

Adapt folders to real ownership and existing conventions.

Do not create empty folders simply to match the example.

Every exported asset must have a clear owner and
a real consumer or documented preparation purpose.

Avoid duplicated theme assets when the artwork is
genuinely identical.

Do not falsely share assets that differ significantly
between the four approved references.

Do not store all cutouts in a single miscellaneous
folder with unclear filenames.

============================================================
21. SOURCE ARTWORK AND WORKING FILES
============================================================

Preserve the approved originals without modification.

Store useful intermediate artwork separately from
optimized runtime assets.

Useful intermediate material includes:

- Extraction masks.
- Alpha masks.
- Reconstructed background patches.
- Original crop coordinates.
- Layered master-composition files.
- Source image provenance.
- Asset generation/editing scripts when applicable.

Use a dedicated design-source location under the
existing design documentation structure when needed.

Keep runtime asset loading separate from working files.

Do not put large unoptimized PSD-like working material
into the public runtime asset directory.

Do not retain unlimited temporary generations.

Keep the final chosen asset and useful reproducible
source material.

============================================================
22. ASSET MANIFEST CONTRACT
============================================================

Create or update a maintainable asset manifest.

For each asset define relevant metadata:

- id
- theme
- source
- file path
- original canvas width/height
- crop bounds
- placement X/Y
- rendered width/height
- anchor
- z/layer order
- clipping/mask reference
- animation role
- extraction or reconstruction provenance

Keep the manifest aligned with the exact reference
coordinate system.

Use measured coordinates.

Do not maintain duplicated placement values scattered
across unrelated TypeScript and SCSS files.

Do not unnecessarily force all assets to full-canvas
runtime dimensions.

During authoring, full-canvas transparent layers are
acceptable for validation.

During runtime, prefer optimized transparent assets
with recorded placement metadata.

============================================================
23. LAYER COMPOSITING ORDER
============================================================

Build the final static room in a controlled order.

Recommended composition:

LAYER 0:
Exterior panorama for the selected theme.

LAYER 1:
Interior shell with transparent outdoor openings.

LAYER 2:
Permanent architecture, window frames, shelves,
ceiling beams and fixed wall fixtures.

LAYER 3:
Behind-object details and shadows.

LAYER 4:
Wall logo and mounting treatment.

LAYER 5:
Large furniture and washing machine body.

LAYER 6:
Washing machine drum background and live preview area.

LAYER 7:
Machine rims, glass reflections and control face.

LAYER 8:
Wooden Project Board and clean board surface.

LAYER 9:
Board pins, cards and real DOM content.

LAYER 10:
Towels, plants and midground decorative objects.

LAYER 11:
Left and right raccoon characters.

LAYER 12:
Laundry baskets, stools, cubes, floor props
and other foreground objects.

LAYER 13:
Localized lighting, reflections and appropriate
foreground atmospheric effects.

LAYER 14:
Independent global HTML/CSS controls.

The exact depth of an object must reflect the source.

For example:
- A vine may hang in front of the board.
- A machine may hide part of a wall shadow.
- A raccoon may stand in front of the washer.
- A basket may stand in front of machine edges.

Do not rigidly put all objects of one category
in the same z-index if the source shows a more
complex overlap.

Use finer layering only when required.

============================================================
24. MANDATORY STATIC RECOMPOSITION VALIDATION
============================================================

This is a critical acceptance gate.

Before functional overlays or animation are added,
reconstruct the original static reference scene
using the extracted layers.

Render the composition at exactly:

1672 x 941 pixels.

For each theme:

- Render the reconstructed composition.
- Compare it against the approved reference.
- Check object silhouettes.
- Check alignment.
- Check scale.
- Check perspective.
- Check outlines.
- Check lighting.
- Check missing details.
- Check transparency holes.
- Check unwanted duplicate objects.
- Check residual extraction halos.

Use visual overlays, difference images or
region-based comparisons where useful.

A global pixel-difference metric may be informative,
but it is not sufficient because reconstructed
hidden areas and dynamic UI placeholders differ
intentionally from the reference.

Evaluate the regions that should remain identical.

Mask out intentional dynamic-content differences.

If the machine, board, logo or characters visibly
shift relative to their approved positions,
the phase is NOT complete.

Do not fix major extraction geometry errors with
arbitrary CSS transformations.

Correct the asset and its metadata.

34. PERFORMANCE AND RESOURCE MANAGEMENT
============================================================

Asset quality must not create unnecessary runtime cost.

Optimize final artwork for the browser.

Requirements:

- Avoid unnecessary oversized transparent canvases
  in runtime delivery.
- Use suitable optimized formats.
- Preserve alpha quality.
- Record true intrinsic dimensions.
- Lazy-load secondary artwork where appropriate.
- Do not constantly recreate image elements.
- Avoid excessive compositing layers.
- Avoid uncontrolled CSS filters.
- Dispose animation resources correctly.
- Stop inactive loops and timers.
- Respect reduced-motion settings.
- Avoid expensive JavaScript animation per frame.
- Preserve existing project preview cache behavior.

The overall application must continue supporting
projects exceeding 100,000 blocks.

Do not alter renderer hot paths unless required
by a verified bug.

============================================================
35. TESTING STRATEGY — REDUCE UNNECESSARY REPETITION
============================================================

The current process has spent excessive time repeating
tests after small visual changes.

For this Goal, prioritize correct visual production.

DURING EXTRACTION:

- Inspect generated files.
- Check transparency.
- Check image dimensions.
- Check layer alignment.
- Check compositing output.
- Check missing objects.

Do not run the full application suite after every
crop, mask or artwork adjustment.

DURING SCENE ASSEMBLY:

- Use browser visual inspection when available.
- Compare the render against the reference.
- Fix visible composition problems.
- Fix immediate TypeScript/build errors.

AT A MEANINGFUL CHECKPOINT:

- Run relevant targeted tests.
- Run TypeScript checks.
- Run production build.
- Run encoding/format checks.
- Run git diff --check.

AT THE FINAL IMPLEMENTATION MILESTONE:

- Run the full automated test suite.
- Run all relevant typechecks and build verification.
- Run persistence/preview regression tests.
- Run performance checks only when relevant code
  or resource hot paths were changed.

Codex must perform available automated verification
itself.

Do not transfer command-line testing work to the user.

Do not claim tests passed if they were not executed.

The priority is to reduce redundant test frequency,
NOT to hide regressions.

============================================================
37. ASSET QUALITY GATES
============================================================

An asset is NOT complete merely because its file exists.

Each asset must satisfy:

1. Extracted from the correct original theme.
2. Retains the original visible design.
3. Preserves the correct shape and perspective.
4. Has clean transparency.
5. Contains no unwanted segmentation halo.
6. Has correctly reconstructed hidden portions
   where independent composition requires them.
7. Uses the correct canvas coordinate system.
8. Has complete manifest metadata.
9. Is saved in the correct folder.
10. Recombines correctly with adjacent layers.
11. Does not create duplicate objects.
12. Is actually used or explicitly retained
    as a reproducible design source.

A theme cannot pass static acceptance if any critical
asset is missing, visibly misaligned or replaced by
an inaccurate new illustration.
